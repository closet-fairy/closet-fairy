# create-pr

현재 브랜치로 **Draft PR**을 만든다. PR 본문은 템플릿을 그대로 두고, AI가 채운 본문 초안은 **채팅으로만** 전달한다. 사용자가 초안을 다듬어 직접 붙여넣은 뒤 "Ready for review"를 누르면 리뷰 봇이 리뷰를 시작한다.

## 1. 사전 확인

아래 중 하나라도 해당하면 PR을 만들지 않고 사용자에게 알린 뒤 멈춘다.

- 현재 브랜치가 `main`인 경우
- 커밋되지 않은 변경 사항이 있는 경우. 커밋은 별도 지시가 있어야 하므로 스스로 커밋하지 않는다.
- 베이스 브랜치 대비 커밋이 없는 경우
- 이 브랜치로 이미 열린 PR이 있는 경우. 이때는 기존 PR 주소를 알려준다.

브랜치 이름이 루트 `CLAUDE.md`의 브랜치 형식을 따르지 않으면 그 사실을 알리되, 멈추지는 않는다.

## 2. 베이스 브랜치

기본 베이스는 `main`이다. 현재 브랜치가 `main`이 아닌 다른 브랜치에서 갈라져 나온 것으로 보이면, "4. 생성 전 확인"의 질문 4로 베이스를 확인한다.

## 3. 변경 분석

베이스 대비 변경 사항을 확인한다.

```bash
git log <base>..HEAD --oneline
git diff <base>...HEAD --stat
git diff <base>...HEAD
```

## 4. 생성 전 확인

`AskUserQuestion`으로 아래 질문을 한 번에 묻는다. 사용자가 답하기 전에는 푸시하거나 PR을 만들지 않는다.

PR 제목은 `<type>: <subject>` 형식이며, 질문 1에서 받은 `<type>`과 질문 2에서 받은 `<subject>`를 이어 붙여 만든다. (예: `feat: 코디 추천 추가`)

질문 1 또는 질문 2의 문구에 "답하면 원격에 푸시한 뒤 Draft PR을 만듭니다"를 함께 적는다. 푸시가 필요 없으면 "Draft PR을 만듭니다"만 적는다. 질문에 답하는 것을 푸시와 PR 생성에 대한 승인으로 본다.

### 질문 1: 작업 유형

- 루트 `CLAUDE.md`의 "커밋 메시지 컨벤션" 타입 중, 변경 내용에 가까운 것을 선택지 최대 개수만큼 추려 제시한다. 가장 적절한 타입을 첫 번째에 두고 `(Recommended)`를 붙인다.
- 각 선택지 설명에는 커밋 메시지 컨벤션 표의 해당 타입 설명을 그대로 적는다.
- 선택지에 없는 타입은 사용자가 "기타"로 직접 입력할 수 있다.

### 질문 2: 제목

- 타입을 뺀 `<subject>` 부분의 후보를 선택지 최대 개수만큼 제시한다. 가장 적절한 후보를 첫 번째에 두고 `(Recommended)`를 붙인다.
- 사용자는 "기타"로 직접 입력할 수 있다.

### 질문 3: 라벨 (복수 선택)

- 레포의 라벨을 `gh label list`로 찾아 선택지로 제시한다. 이모지 등이 바뀌었을 수 있으므로 라벨 이름을 추측하지 않는다.
- 바뀐 경로를 기준으로 추천하는 라벨에 `(Recommended)`를 붙인다.
    - `frontend/` 아래가 바뀌었으면 이름에 "프론트엔드"가 들어간 라벨
    - `backend/` 아래가 바뀌었으면 이름에 "백엔드"가 들어간 라벨
    - 둘 다 아니면 이름에 "공통"이 들어간 라벨

### 질문 4: 베이스 브랜치 (필요할 때만)

"2. 베이스 브랜치"에서 베이스가 애매하다고 판단한 경우에만 묻는다. `main`과 감지된 브랜치를 선택지로 제시한다.

## 5. PR 생성

승인을 받으면 필요한 경우 푸시한 뒤 PR을 만든다. 본문은 템플릿 파일을 그대로 쓴다.

```bash
gh pr create --draft --base <base> --title "<title>" --body-file .github/pull_request_template.md --assignee @me --label "<label>"
```

라벨이 여러 개면 `--label`을 여러 번 쓴다.

## 6. 본문 초안 전달

PR을 만든 뒤, `.github/pull_request_template.md`를 읽어 **템플릿 전체**를 채운 초안을 채팅으로 전달한다. 리모트의 PR 본문은 수정하지 않는다.

- 사용자가 그대로 복사해 붙여넣을 수 있도록, 초안 전체를 하나의 마크다운 코드 블록으로 감싼다. 초안 안에 코드 블록이 들어갈 수 있으므로 바깥은 백틱 네 개(` ```` `)로 감싼다.
- 템플릿의 제목 구조는 그대로 두고 각 칸에 내용을 채운다.
- 템플릿의 `<!-- -->` 안내 주석은 PR을 직접 작성하는 사람을 위한 문구이므로, 마지막 안내 주석을 포함해 초안에서 모두 뺀다.
- 채울 내용이 없는 칸은 제목만 남기고 내용을 비운다.
- 초안은 리뷰어 등 다른 사람이 읽을 문서다. 확인 요청처럼 사용자에게 건네는 말은 초안에 넣지 않고 채팅에 따로 적는다.
- 목록 기호는 `*`가 아니라 `-`를 쓴다.

칸별로 아래를 따른다.

| 칸 | 채우는 방법 |
| --- | --- |
| 관련 이슈 | 이 작업을 하는 동안 사용자가 언급한 이슈가 있거나, 브랜치 이름·커밋 메시지에 이슈 번호가 있으면 `- 관련 이슈: #12`처럼 채운다. 여러 개면 쉼표로 이어 적는다. 없으면 템플릿 그대로 `- 관련 이슈: -`로 둔다. |
| PR 설명 | 커밋과 diff를 바탕으로 무엇을 왜 했는지 적는다. |
| 참고사항 | 코드에서 보이는 임시 처리(모킹, 하드코딩, TODO 등)를 **후보로만** 적는다. 이 칸의 내용은 리뷰 봇이 지적하지 않는 면책 대상이 되므로, 의도된 결함이라고 단정하지 않는다. 적은 후보가 의도된 것인지는 채팅에서 사용자에게 확인을 요청한다. 후보가 없으면 내용을 비운다. |
| 스크린샷 또는 영상 | AI가 첨부할 수 없으므로 내용을 비운다. 변경 범위만 보고 스크린샷이나 영상이 필요 없다고 단정하지 않는다. |

마지막으로 PR 주소를 알리고, 초안을 붙여넣은 뒤 "Ready for review"를 눌러야 리뷰 봇이 리뷰를 시작한다고 안내한다.
